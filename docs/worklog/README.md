## เขียนเมื่อไหร่

| สัญญาณ | ทำอะไร |
|---|---|
| จะพัก / ปิดแชท / เลิกทำวันนี้ | บันทึก 1 entry |
| **จะย้ายไปแชทใหม่ (context เต็ม)** | บันทึก + ทำสรุปส่งต่อ (ดูข้างล่าง) |
| ปิด issue หรือ merge PR เสร็จ | บันทึก 1 entry |
| เจอบั๊กที่เสียเวลาเกิน 30 นาที | บันทึก **แม้จะยังแก้ไม่ได้** — ยิ่งแก้ไม่ได้ยิ่งต้องเขียน |

ถ้าใช้ Claude Code: skill `luma-project` สั่งให้ AI บันทึกให้เองเมื่อเห็นสัญญาณพวกนี้
ถ้าใช้ Codex หรือ AI ตัวอื่น: บอกมันตรงๆ ว่า *"ก่อนจบ ช่วยสรุปลง `docs/worklog/<ไฟล์ของฉัน>` ตามแม่แบบ"*

## แม่แบบ 1 entry — เพิ่มไว้**บนสุด** (ใหม่ → เก่า)

```markdown
## YYYY-MM-DD · #<เลข issue> <หัวข้อสั้นๆ>

**branch**: `<ชื่อ branch>` · **สถานะ**: กำลังทำ / รอรีวิว / เสร็จแล้ว

**ทำอะไรไป**
- <ไฟล์ที่แก้> — <ทำอะไร>

**ตัดสินใจอะไรไว้** (เขียนเฉพาะที่มีทางเลือกอื่น)
- <เลือก A ไม่เลือก B เพราะ...>

**ลองแล้วไม่ได้ผล**
- <วิธีที่ลอง> — <พังยังไง>

**ค้างอยู่ / ทำต่อจากตรงไหน**
- <ขั้นตอนถัดไปแบบเจาะจง ไม่ใช่ "ทำต่อให้เสร็จ">

**รออะไรจากใคร**
- <คน/issue ที่รอ — ถ้าไม่มีให้เขียน "ไม่มี">
```

> **"ค้างอยู่ตรงไหน" คือช่องที่สำคัญที่สุด** — เขียนให้ตัวเองในอีก 3 วันข้างหน้าอ่านรู้เรื่อง
> ❌ *"ทำ migration ต่อ"* → ✅ *"รัน `flask ... db migrate` แล้ว แต่ยังไม่ได้อ่านไฟล์ที่ autogenerate ออกมา"*

## สรุปส่งต่อ ตอนย้ายแชท

นอกจากลงไฟล์แล้ว ให้คัดลอกอันนี้ไปวางเป็น**ข้อความแรกของแชทใหม่**:

```markdown
## ส่งต่อจากแชทก่อน — <วันที่>

**ผมคือคนที่ <1/2/3>** · branch: `<ชื่อ branch>` · issue: #<เลข>

**ทำไปแล้ว**: <ไฟล์ + ทำอะไร>
**ค้างอยู่ตรงไหน**: <ขั้นตอนถัดไป>
**ติดปัญหา**: <ปัญหา + วิธีที่ลองแล้วไม่ได้ผล>
**ห้ามลืม**: <ข้อตกลงที่คุยกันไว้>

อ่าน `docs/START_<n>_*.md` และ `docs/worklog/<n>-*.md` ก่อนเริ่ม
```

## กติกา

1. **ห้ามใส่ secret / รหัสผ่าน / token / path ที่มีชื่อผู้ใช้จริงของเครื่อง** — ไฟล์นี้ขึ้น git และ repo เป็น public
2. entry ใหม่อยู่บนสุดเสมอ
3. เขียนสั้นได้ แต่ **ช่อง "ค้างอยู่ตรงไหน" ห้ามว่าง**
4. บันทึกผิดแล้วรู้ทีหลัง → **แก้ entry เดิม** อย่าปล่อยข้อมูลผิดไว้ให้คนอื่นอ่าน
